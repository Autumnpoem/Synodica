# 桌面端、额度浮窗与角色头像

本说明由 Codex 编写。日期：2026 年 10 月 31 日。

## 打开 App

Mac Apple 芯片版本使用 `Synodica-0.5.5-mac-arm64.dmg`；Windows 版本使用 `Synodica-0.5.5-win-x64.zip`。安装包在项目 GitHub Releases 页面列出后，可按平台下载；Mac 打开 DMG 后把 App 拖入“应用程序”，Windows 解压 ZIP 后运行 `Synodica.exe`，并保留整个解压目录。

这些是本地构建包，未进行 Apple 公证或 Windows 代码签名。macOS Intel 安装包尚未构建。Windows 包的生成不等于已在 Windows 真机运行验收。

首次启动默认打开本地办公室。后端、对话和设置保存在应用的数据目录；重新安装程序时不要删除应用数据。更新后沿用原数据目录。浏览器开发预览与正式 App 可能使用不同的数据目录。

## 使用同一个服务器办公室

1. Mac/Windows App 打开“设置 → 通用 → 办公室”，填写自己的服务器 HTTPS 网址和办公室访问令牌，点击“连接”。也可以通过 App 的桌宠菜单打开“切换办公室”。
2. 手机直接在浏览器打开同一个 HTTPS 网址，输入同一办公室访问令牌。
3. 连接后，各端共享服务器保存的对话、项目、任务、头像、审批与纠正记录。额度也来自该服务器执行账号。
4. App 只记住服务器网址和连接模式，访问令牌不保存到配置文件。完全退出再打开远程 App 时，需要重新输入令牌。服务器不可达会显示连接错误，保留远程选择。
5. 点击“切回本地”可回到这台电脑自己的办公室。两套数据各自保存，切换不会合并对话或搬运模型登录。从本地切到远程时，本地正在执行的任务继续运行；完全退出 App 才会关闭本地后台。切换时会暂时停下本地桌宠，回到本地后按原有开关恢复，避免同时出现两只桌宠。

远程办公室应部署本次同版本的前端和后端。手机和 App 连接的必须是同一个服务器网址；各自运行一个本地服务会得到不同办公室。

## 用量与额度悬浮窗

- 网页右下角“额度”打开页内浮窗，可以拖动、收起、关闭，再从“额度”按钮打开。位置与开关保存在该设备浏览器。
- 在 App 内打开页内浮窗，点击“桌面悬浮窗”，即可得到独立窗口。App 的桌宠菜单也有“打开额度悬浮窗”。
- 独立窗口支持置顶、取消置顶、收起和关闭。关闭额度窗不会关闭办公室或桌宠。
- 浮窗和完整“用量与额度”页面读取同一份账户报告。多个成员共用账号时合并显示；不会为每个人虚构独立额度。
- 悬浮摘要优先显示“剩余可用”：例如五小时已用 24%，显示剩余 76%；每周、每月同理。DeepSeek 和 Kimi 开放平台显示余额与币种；Kimi Code 显示平台返回的额度周期。重置时间及额外模型额度可以展开查看。没有报告数字时不会显示成 0%。
- 桌宠右键菜单可以打开用量页面、读取账户摘要。浮窗和桌宠可以同时使用。

实际支持的额度按来源显示：Codex/Claude 的订阅周期、Kimi Code 官方返回的周期、DeepSeek 钱包等。没有凭据、未授权、接口不支持或查询失败时，显示对应状态；“未报告”不代表额度为零。当前 Gemini Google 订阅没有接通可靠的实时余额来源，显示“无用量来源”。

## 头像库

“设置 → 通用”可以更换自己的头像；团队成员资料可以更换成员头像。展开“从可爱头像库选择”，可选 13 种画像：兔子经理、猫头鹰技术主管、狐狸开发、企鹅运维、小熊运营、河狸后端、小狗客户顾问、小熊猫测试、松鼠研究、猫咪设计、水獭产品、仓鼠文档、哈士奇评审。

默认画像按职责匹配；选择其他画像只改变外观，不更换角色、服务商或模型。已有上传头像优先保留。“恢复默认头像”回到按角色匹配的画像。也可以上传自己的 PNG、JPEG、WebP 或 GIF（不超过 2 MB）。头像保存在办公室服务器，在其他设备上同步。

## 人设与默认模型

人设和模型分别保存。人设包括名字、职位、负责范围、性格设定和工作流职责；服务商与模型决定由哪个 AI 扮演这个角色。

在“新建群聊”或“新建项目”里搜索并勾选已有角色即可复用。没有合适的角色时，点击“新增角色”，填写名字、职位和性格设定，选择默认模型后保存。新增角色会自动勾选，之后其他对话也可以选到。支持纯中文名字；添加或取消角色不会清空正在填写的对话名称和项目需求。新增角色窗口按 Esc 只返回外层草稿。

右侧资料标题已放大加粗。已有角色的“角色与人设、外观、项目工作流、工具、MCP、记忆”默认折叠，“默认模型”保留展开。编辑表单时页内桌宠与额度浮窗会暂时隐藏，关闭表单后恢复。

开发团队模板为各个席位预填默认服务商和模型，创建时可以调整。已有成员可以通过侧边栏成员的“更多 → 编辑资料 → 默认模型”更换服务商和模型，再点击“保存”。切换服务商时会预填该服务商的模型默认值，可以继续修改；`default` 表示使用对应 CLI 自己配置的模型。

例如，技术主管原来由 Claude 扮演，之后可以改为 Codex；不需要删除角色或重新创建项目。职责与性格设定仍保留。更换服务商后，也应检查该角色的工具选项，因为各服务商支持的工具不同。

本次已在独立测试办公室实际切换并保存 Claude → Codex，核对名字、职位、负责范围、性格和工作流职责不变，再恢复原设置。未发起付费模型调用。

## 原版透明桌宠

办公室页面的桌宠区使用 PC2005-cloud/dsh-pet 0.3.8 的原始运行时和动画。点击“启动桌宠”后，可以在原版设置里调整尺寸、显示范围和宠物。

本地 App 使用原版透明桌面助手。连接服务器的 App 使用本机透明窗口加载原版动画与交互，跟随服务器的工作状态；无图形界面的 Ubuntu 只运行宠物宿主，不启动桌面窗口。

“跟随”可以选择整个团队、项目或某位成员。工作、等待审批、完成等来自真实任务事件。原版 DSH 专属的独立宠物聊天、碎碎念和通知服务尚未接入；当前桌宠不会自行发起模型对话。

## 中途纠正

项目运行时可以停止当前执行，输入纠正要求后继续。已有讨论、任务和纠正记录保留。多端同时编辑同一项目或任务时，过期页面会收到冲突提示；刷新后再编辑。停止、暂停和取消任务不因页面版本稍旧而被拒绝，已经结束的任务仍遵守原有状态规则。

订阅的登录位置和步骤见 [订阅接入指南](subscriptions/README.md)，服务器安装见 [Ubuntu 部署](Ubuntu部署.md)。


## 0.5.1 规划讨论

角色职责是主要分工，不限制有依据的跨职责意见。公司与实验室模板在自动模式下启用一轮只读规划讨论；自定义团队可以在“设置 → 通用 → 规划讨论”手动开启。看板保留原始异议、参与状态和负责人逐条处理理由，需要你裁决的意见会阻止开始或恢复执行。详情与首次对话示例见[快速开始](快速开始.md)。

## 0.5.3 群聊继续讨论与定向纠正

群聊中明确要求成员继续讨论某个问题时，可以不再生成 `@everyone` 而继续多轮对话。至少需要两名未静音成员，默认最多四轮，并受消息与单人回复预算约束；该路径不调用普通模型路由。明确停止或否定不属于继续讨论；多个 `@名字` 按全局范围处理。结束提示、项目流程提示气泡和侧边栏预览已本地化。

普通群聊中的 `@名字` 纠正或引用回复可只中断目标成员及其待处理审批，其他成员继续。被纠正成员等待当前轮次和既有队列结束后再单独回复；不同目标的纠正不会相互覆盖。私聊与单个 `@名字` 仍然保持独占，单人点名优先于全组讨论。项目工作流纠正仍作用于整个项目。

本版只调整讨论和纠正的交互流程，没有新增服务商、模型、权限或认证方式。完整的版本变化见[更新记录](../../CHANGELOG.md)。
