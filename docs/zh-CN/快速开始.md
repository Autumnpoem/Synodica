# Synodica 快速开始

[English](../en/getting-started.md)

Synodica 是一个共享工作空间，可以保存 AI 角色、群聊和项目任务。本指南介绍 0.5.3 桌面包及源码运行方式，不会替你配置账号或调用模型。

可在外观设置中选择**浅色**、**深色**或**跟随系统**。从同一办公室打开的额度面板和桌面额度浮窗会跟随办公室的外观偏好。

## 0.5.2 新增接入能力

macOS 上优先使用 `PATH` 中的 `codex`；找不到时，可发现已安装的 ChatGPT 或 Codex 桌面应用附带的 CLI，并复用现有登录，不导出令牌或另装一份 CLI。应用调用的是 CLI 引擎，不是桌面 UI。Windows 不支持该桌面应用内 CLI 探测。

Claude Code／Anthropic 兼容网关可作为独立服务商配置，明确选择 x-api-key 或 Bearer 认证，并填写网关根地址、该网关自己的凭据和精确模型 ID。改变端点来源后需要新的凭据；官方密钥和 OAuth 登录不会自动转发。此配置不会修改全局 Claude 设置或登录状态。设置页面也完成了中文文案和布局修正。以上说明的是可配置能力，不代表已验证真实网关、账号或模型调用。详见[中转接入指南](subscriptions/07-Claude中转与Antigravity.md)。

## 安装桌面版

按电脑选择安装包：**Apple 芯片 Mac** 使用 `Synodica-0.5.3-mac-arm64.dmg`；**64 位 Windows** 使用 `Synodica-0.5.3-win-x64.zip`。发布页列出这些文件后，可从项目 GitHub Releases 页面下载。Mac 打开 DMG 后，将 Synodica 拖到“应用程序”。Windows 解压 ZIP 后运行 `Synodica.exe`，并保持解压目录中的文件在一起。

安装包未签名；Mac 版也未经公证。操作系统可能显示警告或阻止打开。只有在确认来源可信、核对过发布文件后再决定是否继续；不要关闭或绕过操作系统的安全保护。Windows 包内容已检查，但尚未在 Windows 真机上验收。当前桌面版面向 Apple 芯片 Mac，不包括 Intel Mac。Windows 尚未进行硬件运行验收，且 Windows 不支持探测 ChatGPT／Codex 桌面应用内附带的 Codex CLI。

## 从源码运行

安装 Node.js 22 或更新版本及 npm，然后执行：

```sh
git clone https://github.com/Autumnpoem/Synodica.git
cd Synodica
npm ci
npm run pet:install
npm run build
npm start
```

打开服务端显示的本地地址。`pet:install` 会安装固定版本的桌宠运行时。请妥善保管 `team.json`、`data/`、服务商凭据和构建包。构建后如需启动原生桌面窗口，可执行 `npm run desktop`。

### 更新已有源码目录

先停止运行中的服务，在已有项目目录执行：

```sh
git pull --ff-only
npm ci
npm run build
npm start
```

保留原办公室数据目录和服务商凭据，不要用公开源码覆盖私人运行数据。桌面版请从 Releases 页面选择已列出的对应版本安装包，再按上文平台步骤更新。

## 在实际运行后端的电脑上接入服务商

打开 **设置 → 服务商**，查看已有的服务商条目。Claude Code、Codex 和 Gemini 的 API Key 留空时，会使用运行后端的操作系统用户已完成的官方 CLI 登录。请在同一台电脑、同一系统用户下完成官方登录；共享 Ubuntu 办公室则使用 Ubuntu 服务用户。填入 API Key 后会切换到对应服务商的 API 计费身份。应用不会导入网页 Cookie，也不会把网站会话变成 API 权限。设置里的“导入”是导入角色／人设 JSON 文件，不是导入模型账号或凭据。

Kimi Code 订阅、Kimi 开放平台和 DeepSeek API Key 的配置步骤见[订阅接入指南](subscriptions/README.md)。只在对应服务商设置中保存密钥。订阅与 API Key 可能采用不同的计费身份。服务商状态检查通过，不代表所有模型都有权限，也不保证模型调用一定成功。添加凭据前请先读对应指南，切勿把密钥粘贴到聊天里。

CLI 登录由执行任务的后端使用，不会自动替所有角色切换服务商。在员工资料中，可从模型下拉框选择模型，点“刷新”请求更新目录，也可选择自定义 ID 并手动填写精确的模型 ID。目录会标明来源：上游 CLI、服务商 API，或本办公室已配置的模型。目录用于发现选项，不代表当前账号一定有权限、余额或剩余额度，也不保证请求会成功。如果获取目录需要尚未配置的凭据，可先手动填写模型 ID，之后再配置对应服务商。**default** 表示让已配置的上游 CLI 使用它自己的默认模型；它不代表某个具体 GPT 模型，也不会把一家服务商的模型通用替换成另一家的模型。API Key 接入通常需要选择具体模型 ID。Kimi Code 与 Kimi 开放平台使用不同的凭据和端点，请按账号和计费方式分别配置。若某家没有可读取的额度来源，页面会显示不可用；目前尚未接入 Gemini Google 订阅的实时额度报告。

## 选团队并开始对话

打开 **设置 → 团队 → 默认团队**，选择 **公司团队** 或 **学术／实验室团队**。新建员工时必须填写姓名和职位；提示词可以留空，系统会根据员工职责生成初始提示词，之后仍可编辑。保存前请检查模型；模板建议可以修改。模板创建的是可复用员工，再次应用时会复用已保存员工，不覆盖姓名、提示词或模型选择。需要修改已有员工的默认值时，请打开其资料编辑。新建对话时选择需要参加的员工；新建项目时填写目标并选择参与员工，再到看板检查负责人和评审角色。

可以先与一个角色私聊，熟悉它的回复方式。私聊在本轮中只由该角色回复。在群聊里使用一个明确的 `@名字`，本轮也只由被点名者回复；即使对方提及其他成员，被提及者也不会加入本轮。若消息没有点名，团队设置中的群聊模式会决定由智能调度器选择 1–3 名相关成员、全组参加开场轮次（有文件写入工具的员工会串行执行以保护共享目录），或由第一位成员接手。

如需在群聊中邀请全组，可以使用 `@everyone`，或直接说明“请所有人都对这个计划发表意见”。邀请会点名未静音成员，最多 12 人。每位受邀成员的回复可能消耗其服务商用量；跳过发言不代表同意。

`@everyone` 会开启全组发言轮次：在安全时回复可以并发；配置了文件写入工具的员工则会串行执行，避免同时改写同一工作目录。单独 `@名字` 仍只由被点名员工处理本轮，其他成员不会加入。

从 0.5.3 起，如果你明确要求群聊成员继续讨论某个问题，即使没有再次生成 `@everyone`，也可以继续多轮讨论。至少需要两名未静音成员；这一流程不会调用路由器挑选模型。默认回复预算为四轮，同时受消息与单人预算限制；合适时结束提示会建议“继续讨论”。明确停止或否定的指令会结束讨论，不会被当作继续辩论。多个 `@名字` 按全局范围处理。

普通群聊中的 `@名字` 纠正或引用某位员工的回复，只会中断该员工和必需审批，其他成员可继续工作。被纠正成员会等当前轮次和已有回复队列结束后，再单独接收一次定向回复，不会立即并行启动。项目工作流中的纠正仍作用于整个项目。私聊始终只回复该员工；单个 `@名字` 优先于全组讨论。无效目标和伪造引用会被拒绝；针对不同成员的纠正不会互相取消。

可点附件按钮，或把图片拖入、粘贴到输入框。只有当前用户消息附带的图片会交给本轮选中的服务商和模型。已知模型不支持看图时，Synodica 会明确提示；如果支持情况未知，或 CLI 工具无法读取图片，员工应说明无法查看图片，不会假装已经看过。

需要协作交付时，新建项目，描述目标并选择参与角色。在 **设置 → 通用 → 规划讨论** 中选择 **自动**、**开启** 或 **关闭**，并设置参与人数上限（默认 6 人，范围 1–12）。**自动**模式会在项目含有公司或实验室内置角色时启用讨论；只有自定义角色的项目保持原流程。**开启**和**关闭**可覆盖自动选择。

整理文件时，请在员工资料中启用 **Read（读取）**和 **Write（写入）**工具，并选择已配置好文件工具的服务商。Synodica 自建调度器连接 Claude SDK、Codex CLI、Gemini CLI 或 API，不会继承 Codex Desktop 的 Computer Use 插件或桌面权限；目前尚未接入桌面 Computer Use。服务商桌面应用里的 Word、PDF、表格专用技能也不会自动继承。请将整理任务限定在你配置好的工作目录和工具范围内。

点击 **启动规划（Kickoff）** 后，决策负责人先制定计划。随后符合条件且未静音的参与者（不含负责人和评审者）各进行一轮只读讨论，人数不超过设置上限。之后由评审者检查计划，再由负责人决定后续步骤。看板会保留每条意见的原始主张和理由，并由负责人逐条记录“采纳、驳回、未解决、需要用户决定”及处理理由。跳过回复不代表同意；每个被请求的讨论轮次（包括跳过）都会使用一次模型调用，可能消耗服务商用量。单个成员出错不会中断其余成员。

看板会显示参与者和未参与原因。无法保证只读的角色会从本轮规划讨论中略过。例如，配置为可写工具的 Gemini CLI 角色仍可用于普通聊天和实现，但本轮规划中不会自动被邀请，也不会被自动修改工具设置为只读。若意见状态为**需要你决定**，请在看板表单中选择处理方式、填写理由，再点击 **开始**；规划会等待你的决定。未解决的意见会保留在项目上下文中。

如果讨论中途停止，点击 **恢复** 后只会重新询问尚未回复的参与者。纠正会创建新的指令版本，旧讨论迟到的结果会被丢弃，新一轮计划将使用纠正后的要求。

任务运行中，可使用 **停止／纠正** 控件中断并补充要求。小幅纠正可以继续当前工作；若纠正改变了范围，系统会等待你选择恢复当前计划或重新启动规划。纠正内容会保留在项目中，旧任务不会被悄悄重放。

第一次群聊讨论时，可以发：

> 请所有人分别指出这个提案中一个重要风险；如无异议，请明确回复“无反对意见”。每条风险写清主张、证据（或标注为假设）、影响和具体缓解办法。不要声称已经达成共识。

新建项目时，可将下面内容写入项目说明后点击 **启动规划**：

> 做一个小型命令行工具，安全地批量重命名一个文件夹中的文件。请说明假设，提出尽可能精简的计划，列出负责人、依赖关系和可测试的验收标准，然后等我评审后再开始实现。

处理看板上的反对意见时，可在理由框填写具体决定，例如：

> 采纳 O-1，因为迁移可以在每个批次完成后回滚；请把回滚检查加入验收标准。

再按实际决定选择**采纳**、**驳回**或**保留为未解决**。若负责人将意见标为需要你决定，填写并提交处理理由后，再点击 **开始**继续。

## 手机连接同一个办公室

要共享办公室，先在配置好 HTTPS 的服务器上部署后端，再让 Mac／Windows 应用连接该服务器网址，并在手机浏览器打开同一个网址。使用该办公室的访问令牌登录。各端共享服务器上的对话、项目、服务商登录和账户用量。手机浏览器登录模型厂商，不会代替服务器登录。部署步骤见 [Ubuntu 部署](Ubuntu部署.md) 和[多端登录位置说明](subscriptions/06-Ubuntu与多端登录位置.md)；本指南不会替你创建公网服务器或网址。

## 常见问题

- **服务商不可用：** 确认 CLI 已安装，并以运行后端的系统用户完成登录；Ubuntu 还需检查服务用户的 `HOME` 和 `PATH`。
- **检查通过但回复失败：** 检查角色选择的模型及账号权限。状态检查本身不是付费推理测试。
- **看不到额度：** 暂不支持或无法获取不等于余额为零。Gemini Google 订阅额度尚未接入。
- **桌宠没有独立聊天：** 内置 dsh-pet 提供桌面陪伴动画；它自己的独立聊天服务尚未接入。
- **Windows 无法启动：** x64 ZIP 内容已检查，但仍待 Windows 真机验收。请保持解压目录完整；不要为此关闭安全保护。
- **手机打开的是另一间办公室：** 核对服务器网址和访问令牌。不同本地办公室之间不会自动合并。

- **桌面宠物与余额：** 在桌面应用中，可在原版 dsh-pet 设置里把显示模式改为 **Desktop**，让宠物显示在应用窗口之外。它的“查看余额”每次只显示本地用量缓存中的一个账户，不会再次查询服务商。需要查看各账户的五小时、每周或每月限额时，请从桌宠菜单打开“用量与额度”或“额度摘要”；具体窗口以服务商报告的数据为准。Mac 主题同步已验证；用户确认原版桌宠可悬浮在应用窗口之外。Windows 真机运行仍未验证。如果尚无当前用量快照、余额显示不可用，请先在“用量与额度”手动刷新一次；桌宠本身不会查询账户。
