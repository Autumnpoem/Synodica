# Synodica 订阅接入指南

适用版本：Synodica 0.5.5。原始核对日期：2026年10月31日；本次版本文案更新：2026年11月2日。本文中的步骤不会替你登录，也不包含任何真实密钥。

这套项目把成员绑定到不同服务商。前三家的订阅通过官方命令行工具已有的登录使用，Kimi 编程套餐通过官方 Kimi Code Key 接入；Claude Code／Anthropic 兼容网关可作为单独服务商配置，需使用该网关自己的端点和凭据。macOS 上 Codex 可在 PATH 无 CLI 时探测 ChatGPT／Codex 桌面应用附带的 CLI；Windows 不支持此探测。设置页面已完成中文文案和布局修正。这些描述不代表真实网关或模型调用已验证。没有统一的账号 Cookie 导入向导，也不需要导出浏览器 Cookie。

## 建议按这个顺序接入

1. 确认任务实际在哪台电脑或服务器执行。
2. 在该机器上完成官方工具登录，或在项目服务商设置中保存相应 API Key。
3. 打开项目的“设置 → 服务商”，检查服务商状态；不要把付费 API Key 填进本应使用订阅的前三家配置。
4. 打开成员资料，选择服务商和该账号可用的模型。配置一个服务商不会自动把现有成员改用它。
5. 如需验证回答，再给这个成员发一句简短消息；这一步会使用你的实际额度。服务商状态检查与额度刷新则不应发起模型推理。
6. 打开“用量与额度”，确认显示的账户类型、来源、查询时间和状态。

## 登录与额度查询分开看

“服务商已登录”表示执行适配器找到了可用的登录方式，不代表每一款模型都有权限，也不代表每家的实时额度都能读取。尚未查询、未配置、接口不支持、已过期、查询失败和零余额是不同状态。

多个成员共用同一订阅时，会共用该账号的额度。界面不为每个成员虚构一份独立额度。Google 的调用接入与 Google 实时额度查询也是两件事，当前验收版没有接通 Gemini Google 登录的实时额度来源。

## 资料保管

密码、Cookie、OAuth 登录文件和 API Key 不应粘贴进项目群聊、需求、日志或截图。API Key 只填入相应服务商的密码输入框。备份项目数据时，服务商配置可能含密钥，应按私人资料保管，不要放进公开代码仓库。

## 讨论和点名行为

0.5.3 支持群聊围绕明确提出的问题继续多轮讨论，无需每轮都生成 `@everyone`；至少需要两名未静音成员，默认四轮并受预算约束。明确停止或否定会结束讨论。单个 `@名字` 和私聊仍只由目标成员回复。

普通群聊中，针对单人的纠正或引用回复只中断目标成员及所需审批；其他成员继续工作。目标成员等待当前回复轮次与已有队列结束后再单独回复。项目工作流纠正仍作用于整个项目。此版本没有修改服务商、模型、权限或认证配置。详见[快速开始](../快速开始.md)及[按版本查看更新记录](../../../CHANGELOG.md)。


Codex Desktop 的引擎识别见 [ChatGPT／Codex](02-ChatGPT-Pro.md)。中转接入见 [Claude 中转与 Antigravity](07-Claude中转与Antigravity.md)。服务商页面提供可折叠的账号接入说明；原有账号不会因升级自动改成中转或 API 计费。
